## Diagnostico y cambios

1. La normalizacion de pedidos calculaba todas las comisiones de ambos roles
   antes de recuperar los importes historicos guardados. Ahora calcula solamente
   los valores faltantes. Rechazos/anulaciones y aprobaciones comerciales
   conservan su circuito anterior. No es un recalculo de liquidaciones.
2. Administradores con la misma proyeccion y version repetian las huellas de
   todos los registros. Ahora comparten huellas inmutables con limite de memoria,
   pero cada cursor sigue ligado a su propio usuario y version.
3. La primera respuesta completa se comprimia nuevamente para cada administrador.
   Los clientes nuevos pueden reutilizar sus bytes comprimidos (maximo 16 MiB,
   tres proyecciones, 60 segundos). Cada cambio de version invalida la cache.
   El cursor privado viaja en X-State-Cursor. El contrato anterior sigue disponible
   para clientes que no solicitan bootstrap=shared-v1. Vendedores y repartidores
   conservan sus proyecciones privadas y no comparten esta respuesta por rol.
4. Al instalarse el service worker por primera vez, la pagina se recargaba y
   repetia el arranque. Se evita exclusivamente esa primera recarga redundante;
   las actualizaciones de un controlador existente conservan la recarga unica.

Se mantienen el limite de una sincronizacion pesada concurrente, las validaciones
de permisos, el control de versiones y las operaciones atomicas/idempotentes.
No se recortaron historiales ni se cambiaron criterios de stock, saldos o precios.
